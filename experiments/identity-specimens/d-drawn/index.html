Software organizations are factories. Most have one bottleneck, and it is rarely the developers.

I'm Martin Trenker. I've written software for 25 years, most of them inside organizations where good engineers were slowed down by the system around them. clean.dev is where I work out, in public, how clean code, real agility and AI behave inside a team: not as rituals or tools, but as a factory with constraints you can find and fix.

I join teams as a technical lead or solutions architect and stay close to the code, because that is where the factory tells the truth. Everything here, including the site itself, is built in the open.

Where the work waits

A team of 5 developers and 1 reviewer has 14 changes waiting for review.

Add 2 developers and 20 changes wait.

A delivery system with five stations. Numbers are illustrative.

Work flows from Ideas through Refinement, Development and Review to Release. The longest queue sits in front of Review, where 14 changes wait for one senior reviewer. Development has 9 changes in progress for 5 developers. Adding developers increases the review queue; the constraint is review capacity.

03Writing

I'm done with autonomous "Agent Fleets"

Draft, 2026. About 9 minutes.

I knew I had lost control when I used my agent fleet to build a dashboard for my agent fleet.

The fleet was working. It took large plans, split them into tasks and sent agents into separate workspaces. Code appeared quickly. What I no longer had was any idea what was going on.

So I asked the fleet to build its own "flightdeck": a web app that ingested all the task folders where I logged every agent turn and a summary as JSONL. The dashboard showed a live view of the agents running across my machines. It was read-only at first. Steering from the dashboard would definitely come later.

The result had a lot of information on the screen. It still wasn't what I needed.

Worse, I had no idea what was going on inside the fleet-generated codebase behind it. It looked like all the other AI projects I had seen. It worked, but it felt neither like an achievement nor like something I wanted to use.

The cost I hadn't planned for

I have always been proud of the skills I earned over the last 25 years. This "productivity boost" slowly chipped away at that pride and replaced it with anxiety. Worse, it took away my love for coding.

I wasn't building the system anymore. I was watching a system get built.

In the fleet workflow, a large plan is split into tasks and sent to agents in separate workspaces; code appears quickly and a dashboard shows activity, but understanding is lost. In the current workflow, one groomed issue becomes one small task, worked in a worktree by an orchestrator, an implementer and a reviewer, then crosses as a pull request into Martin's review before it is merged. The constraint is Martin's review, by design.

Two ways to work with agents
Workflow Stations Constraint
Fleet Large plan, split into tasks, agents in separate workspaces, code appears, dashboard. Ends in no understanding. none marked
Now Issue, one small task, worktree (orchestrator, implementer, reviewer), pull request, review by Martin, merge. review by Martin
